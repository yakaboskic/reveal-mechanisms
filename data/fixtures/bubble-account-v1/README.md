## Local database seed

The seed requires an existing workspace owner, the exact `reveal_workflow_local` application prefix, and the already imported source gap. Supply the local runtime environment explicitly. Environment variables already set in the shell take precedence over `--env-file`; a mismatched configured prefix is rejected. No implicit `.env` file is read and no schema migration runs.

```sh
.venv/bin/python scripts/seed_bubble_account.py --dry-run \
  --env-file /absolute/path/to/local-runtime.env \
  --table-prefix reveal_workflow_local --owner WORKSPACE_OWNER_UUID

.venv/bin/python scripts/seed_bubble_account.py --apply \
  --env-file /absolute/path/to/local-runtime.env \
  --table-prefix reveal_workflow_local --owner WORKSPACE_OWNER_UUID \
  --receipt .runtime/bubble-account-seed-receipt.json

.venv/bin/python scripts/seed_bubble_account.py --verify \
  --env-file /absolute/path/to/local-runtime.env \
  --table-prefix reveal_workflow_local --owner WORKSPACE_OWNER_UUID
```

Dry-run reads the configured database/catalog but uploads and writes nothing. Apply/verify require a configured versioned S3 store. Apply reads back the actual immutable versions before committing the account, membership, full scientific document, object projections/bindings/observations, grants, citations, and artifact records. It substitutes verified `s3://` locations without changing scientific identity. The receipt records owner, content hash, exact inserted/reused keys, S3 versions/checksums, and local account/gap URLs.

The seed remains private, has `job_id: null`, exposes explicit `fixture_origin` application metadata, and leaves the research statement `not_requested`. It never dispatches research, review, or paragraph jobs or publishes the account. The existing owner is an access principal, not a fabricated author. Repeating the seed re-verifies retained data without updating rows; identical source bytes reuse S3 versions. Other owners can reuse immutable citation/source identities without overwriting the first registry revision.

For future removal, the receipt's `inserted_records` identifies only records inserted by this seed. `reused_records` is not owned by the seed. Do not bulk-delete receipt keys or S3 objects without checking subsequent shared references. Automated removal is intentionally not provided.
