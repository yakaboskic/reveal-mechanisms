# Reveal authoring contract

Version: `reveal.authoring-contract/2`. This scientific contract is shared by local and hosted agents. Start here, then read `input/evidence-index.json`. Use `read_evidence` for exact JSON-pointer selections or text ranges from original artifacts. Supply the indexed artifact ID and SHA-256; follow only a continuation for that same hash, selection and page limit. `content_json` preserves exact source numeric tokens. For long lines or JSON string values, use `mode: text_range` with zero-based Unicode character offset/limit and the string pointer when applicable; returned character and UTF-8 byte locators state the exact window. Inspection is not a scientific query or new observation. Query coverage and reader truncation are different.

New workspaces use DAPPER `0.2.0` at the exact release commit and checksums in the bundled release lock. The locked definitions are in `input/package-sections/authoring-schema-excerpt.yaml`. Complete synthetic draft examples are in `input/package-sections/authoring-examples.json`; they illustrate structure and are never eligible scientific sources. Original artifacts, hashes, source Files and locators remain authoritative. There is no generated record-file tree. Read detailed retrieval diagnostics or vector slices only when needed for an explicit audit.

Investigate scientifically useful gene–GeneSet, gene–factor/Mechanism and GeneSet–factor/Mechanism relationships. Search existing Propositions and Claims first, inspect scope and obtain reuse receipts for selected assessments. Create or reuse distinct supported Claims; there is no quota for relationships or claims. Free-form synthesis remains valid.

For each supported relationship, use a Proposition with `subject_entity`, `relation` and `object_entity` together. Preserve the trusted GeneSet and Mechanism IDs; resolve a discovered factor with `get_factor` and use its trusted materialized object. Keep source factor/gene/set keys, DAPPER IDs and verified external biological identities separate. Use resolve_gene.source_local_id for its exact import/index identity; organism_context is an explicit query constraint, not inferred species. Unresolved source-local genes remain usable within their recorded import scope, but do not establish cross-dataset identity or species.

Use `get_gene_set` for exact definitions and `get_gene_set_members` when membership matters. Co-loading does not prove membership. A perturbation target in a signature name is not automatically a member. GeneSet names alone establish neither membership, biological function nor tissue context.

Every GeneSet-based EvidenceItem needs an inspectable path to the exact GeneSet: through the structured target Proposition, through an assessed `source_claims` relationship, or through `was_derived_from` when its definition, membership or construction actually informed the evidence. In the latter case retain **both** the captured File and exact GeneSet in `was_derived_from`. A GeneSet ID cannot replace a source observation and locator; an unrelated GeneSet cannot serve as a provenance shortcut. Preserve available collection/construction/source dependencies and original authorship. State missing upstream provenance precisely. Do not invent an EvidenceItem `gene_sets` field.

Before synthesis, check each assertion against its factor, gene/set, model/fit, metric, filter, query page/window and coverage status. Check every Proposition, Claim and EvidenceItem separately. A broader sentence cannot be repaired by a disclaimer elsewhere. These TTD mistakes are explicit negative examples:

- Three empty targeted probes on Factor1 do not support “absent from both TTD factors.” Say “no stored nonzero rows in those Factor1 probes”; Factor2 remains untested.
- Absence from Factor2's partial top-60 list does not establish absence from Factor2. Say “not returned in the inspected top-60 window.”
- Small nonzero loading on one factor does not prove exclusive membership in another. Report both observed loadings with their scope.
- Factor names alone do not prove there is no translation-related mechanism. Report that only labels were inspected, or obtain supporting definitions and observations.
- Ratios of loadings are ratios under that stored metric, never biological fold changes or confidence ratios.

Keep joint and marginal metrics distinct and preserve exact numeric precision. Optional source-result Claims may use typed ClaimScores (`LOADING`, with the source metric and interpretation); a loading is not a probability. Empty and diagnostic captures document search coverage but are not independently eligible scientific support. Positive ancestry somewhere in a compound Claim does not support each constituent assertion. Deterministic lint checks structure and source fidelity, not biological correctness.

Seek relevant CFDE grounding; its absence is advisory. Independent imported evidence and authorized source-Claim reuse remain supported. Preserve selected graphs and user-selected anchors. Local KG discovery, typed queries and guarded SPARQL already exist. Only the two advertised BioIndex phenotype operations may call that source, fixed to model `small` and sigma 2, and only when their effective capability is enabled. Missing phenotype evidence limits that path, not factor-based or independent research. Never infer gene identity from uppercase symbols; use a pinned species-qualified crosswalk or state unresolved identity.

Use document-scoped draft IDs such as `urn:reveal:local:<work-id>:<document-id>:proposition-1`, with sibling `claim-1`, `evidence-1`, `score-1` and `account-1`. Trusted assembly supplies final IDs and attribution. Valid historical draft conventions remain accepted.

Local execution: a shell may be available through your chosen agent. Save accounts and notes in `output/`. The kit includes a schema excerpt and reference code, **not** an installed offline validator or DAPPER checkout. Public exploration needs no sign-in. Local literature uses `import_evidence`; do not assume hosted `search_papers`, `read_paper`, `write_account_draft`, `lint_account` or `write_outcome` exist. Check the actual tool catalog. Offline mode keeps `read_evidence` and disables remote calls; missing local artifacts fail clearly without fetching. When connected, export selected receipts/imports/reuse, poll `get_operation`, and call `materialize_evidence_context` to retain the complete verified closure. Download selected anonymous captures before expiry. State whether all cited evidence is present locally.

Hosted execution: use the available bounded reference, graph and literature tools. The protected workspace has no agent shell; write with `write_account_draft` and check with `lint_account`, preserving trusted dependencies. `output/` is the existing `/reveal/output` alias. `write_outcome` records a scoped unsuccessful exploration or authorized prior-account reuse. The worker handles acceptance; never call submission directly or start another hosted run.

Validation and contribution: `validate_submission` retains private validation results and normalized artifacts; it does not accept accounts or publish. Sign-in and write authorization are required. `submit_accounts` separately requests acceptance. Neither action authorizes publishing or paid hosted research. A host may request consent for validation. Anonymous exploration, offline reading and protected contribution remain separate.
